M26 · 知识库自动合并引擎与协作边界加固

  • 新增 flow2spec kb status / check / plan / apply / build 五个知识库命令，覆盖健康检查、变更预演、自动落盘与路由归一化
  • 新增结构化 kb-delta.json 变更协议，支持追加正文、替换正文、更新 frontmatter 与创建 topic 四类受控变更
  • topic 引入整数 revision 磁盘乐观锁；delta 通过 baseRevisions 声明读取基线，版本不一致时在落盘前阻止自动合并
  • 知识库技能改为先形成 delta；提交技能可在唯一定位到当前任务且变更可合并时自动执行检查、预演、合入、构建与复检链路
  • kb build --fix-topics 支持为旧 topic 补齐 revision，便于已有知识库迁入自动合并流程
  • kb status 可将损坏 delta 转为结构化错误；追加或替换正文时，缺失或空白 content 会在解析阶段直接拒绝
  • 显式配置的非法 developerId 会直接报错；git 身份无法规范化时生成稳定 hash id 并给出提示，避免协作任务静默退回单根目录
  • 项目版本进入 3.2.8

M25 · 多人任务按 developerId 隔离

  • 新增 collaboration.enabled 与 collaboration.developerId 配置，支持开启或关闭多人任务进度隔离
  • developerId 按显式配置、git email、git name 的顺序解析；无法取得身份时兼容 legacy 单根任务目录
  • 每名开发者的 todo.json、active/ 与 completed/ 归入独立任务根，任务创建、续作与归档只处理当前开发者上下文
  • .Knowledge/ 继续作为团队共享知识层，个人任务现场与可提交的项目知识分别管理

M24 · Codex 规则镜像修复 + upgrade 步骤 -1 智能预检 + 本仓开发纪律

  • 修复 writeCodexTopicMirrors filter：原 endsWith(".mdc") 遗漏所有 .md 规则文件，导致 flow2spec init codex 后 .codex/topics/ 目录始终为空；扩展匹配 .md 与 .mdc 并统一转成 .codex/topics/*.md
  • f2s-kb-upgrade 步骤 -1 从「无条件后台派子 agent 跑 npm i -g」改为先探测再按需处理：主 agent 顺序前台跑 flow2spec --version + npm view ... version + command -v npx，按 A/B/C 分支决定
    • A 已装且是 latest → 完全跳过升级；步骤 2 首选 flow2spec init
    • B 已装但落后 → 派独立子 agent 后台跑 npm i -g ...@latest（fire-and-forget）；步骤 2 用 npx @latest init
    • C 未装 / latest 未知 → 按 B 处理；探测全失败可整体跳过步骤 -1
  • 步骤 2 命令清单默认形态随步骤 -1 分支选定；补「手动 override」条款与「辅助命令」小节（flow2spec --version / flow2spec update）
  • 新增 f2s-dev-workflow-constraints 规则长文（Cursor / Claude / Codex 三端）：Flow2Spec 双仓自身开发的写盘边界与分发口径——只改 templates、不改配置根、用户驱动分发、双仓一致；本规则只存本仓、不进 templates，下游拿不到
  • 新增 repo-dev-check 自查 skill：本仓提交前逐份改动套「templates vs 配置根」判定表 + 双仓 diff + 分发建议；触发词包括「双仓漂移」「写盘边界」「templates vs 配置根」
  • .Knowledge/topics/f2s-dev-workflow-constraints.md 打薄成路由摘要，指向配置根 rules 长文；matcher 补新触发词（sync:agents / 写盘边界 / 双仓漂移）；index.md 主题一览同步更新关联文档列
  • 本仓专属规则 / skill 的双仓同步义务：内容含双仓包名对照表（@double-coding / @ctrip），双仓采用逐字节一致同步策略，不做包名替换

M23 · f2s-kb-distill 自动判挡 + f2s-kb-upgrade 步骤 -1

  • f2s-kb-distill 砍掉 --fast 参数，内置「轻量挡 / 严格挡」自动判挡：按上游 case、业务源码 Read 数、函数引用数、用户否定信号 4 维度由 agent 选挡
  • 轻量挡跳过下钻量化打分、既有 topic 描述程度评估、决策矩阵与风格对齐；步骤 5 路由 / 步骤 6 落盘永不省略
  • f2s-kb-upgrade 新增「步骤 -1」：进入步骤 0 前派独立子 agent 后台执行 npm i -g <pkg>@latest，不等待完成，主流程立即继续；不受 subAgent 配置约束
  • 步骤 -1 与 cli.js maybeAutoUpdateGlobalInstall 形成互补：升级技能内强制触发，init 末尾兜底触发
  • feedback-closing case 1/2/3 收口块回滚为单命令（去掉 --fast 提示）
  • 命令说明与 commands-reference 增加「执行挡位」节，说明轻量 / 严格两挡触发条件
